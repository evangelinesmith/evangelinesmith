Why a communications strategist has a GitHub

Because the work is systems work, and systems belong in version control.

Content calendars, editorial voice guides, briefing formats, funnel maps, schema specifications — these are structured artifacts with dependencies, revisions, and reuse patterns. Keeping them in Markdown under Git is simply the honest format for what they are. It also means anyone can read the method, fork it, and adapt it without asking me first.

Everything published here is my own framework work. Nothing here is a client deliverable.
